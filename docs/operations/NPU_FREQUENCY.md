# AI-core 频率快照

频率是独立的只读管理证据，不是完整硬件健康、持续锁频或性能资格。Node管理采样、启动/清退边界及个人Demo观察可附带额定频率与当前频率；原精度/性能断言、设备权限、分配和未知租约不因频率读数改变。

固定调用管理员已登记的管理工具及环境文件：`npu-smi info -t common -i PHYSICAL_ID`。只解析明确的`NPU ID`、`Aicore Freq(MHZ)`和`Aicore curFreq(MHZ)`；官方将后两者分别列为额定与当前频率，见[Ascend故障诊断指南 §7.2.3.2](https://www.hiascend.com/doc_center/source/zh/mindcluster/60rc1/faultdiag/faultdiagug/MindX%20DL%206.0.RC1%20%E6%95%85%E9%9A%9C%E8%AF%8A%E6%96%AD%E7%94%A8%E6%88%B7%E6%8C%87%E5%8D%97%2001.pdf)。本机25.7.rc1两张Ascend950PR实际只读回显包含这三个字段，但不代表其他驱动或多芯片板卡已适配。

同次采样最多8条命令，总查询预算3秒、每条最多1秒。查询使用独立进程组，超时仅终止该只读子进程；管理读数后的频率查询有自己的时间戳，不冒充同一时刻或持续观测。队列超时/预算耗尽、缺失字段、重复/多芯片输出、错误设备号、零值和非法数值都保留未知；不把额定频率替代当前频率。超过读取预算的卡标记`not_sampled_budget`，管理员应缩小单Node采集范围或另行适配，不据此显示全卡已测。

`npu-frequency-samples-v1`为Node可选能力；旧Node无频率字段继续原协议，频率保持`not_collected`。字段只接受固定schema/source、物理卡、整数MHz和有界采样时间，去掉原命令、PID及自由文本。Node心跳还需符合原设备合同和新鲜度；历史启动/清退回执按原attempt核验，独立频率时间必须接近对应管理采样。缺失频率不会替代原健康/占用检查，也不阻断结果和清退。

中央原任务的`npu-conditions.json`在最多64份原始快照之外保留频率累计最小/最大、额定频率范围、心跳样本与缺失计数。启动/清退边界引用另计，可能复用同一心跳采样，不宣称额外独立设备读数；被裁剪的低频读数不能丢失。重启沿原账本续记，旧格式在途记录的缺失/裁剪历史不能被后续几个新读数补成完整覆盖。重复时间冲突、倒序值会保留极值并标记顺序不确定。`sampled`只表示这些离散快照可读，不能证明每条kernel执行时的时钟，更不能认证Cube/Vector等时钟域。没有自动修改频率、reset或释放未知资源。

工作流结果/CSV保留频率摘要，网页任务详情展示；个人观察卡片另展示最近当前值与额定值。历史归档原件不回写，旧结果缺字段继续显示未采集。所有性能资格仍为`unverified/false`；获批同卡/工具链性能基线、稳定性策略、业务结果关联自检有效期和真正的非root NPU性能验收尚未完成。

证据范围是资源预留至终态，包括环境准备、计算、空闲等待及产物上传。最小频率可能来自正常空闲降频；不能由一个低值推断实际kernel计时被污染，也不能由一个额定值推断整个计算期间稳定。后续性能资格需把实际计时窗口与同卡/同环境的获批基线、测量时设备条件一起对齐，而不是直接对全区间极值设通用故障阈值。
